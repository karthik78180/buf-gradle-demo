# API Overview

## Payment Transaction API

The Payment Transaction API (`payments.v1`) provides comprehensive support for managing payment transactions in a microservices architecture.

### Core Components

#### Messages
- **Transaction**: Core transaction entity with all payment details
- **Address**: Physical address for billing and shipping
- **CardHolder**: Card holder information including name and email
- **Store**: Merchant store information and location
- **MerchandiseItem**: Individual line items in a transaction
- **ProductDetails**: Container for product/merchandise items

#### Services
- **PaymentsService**: Primary gRPC service for transaction operations

### Key Features

#### REST API Support
All RPC methods are mapped to REST HTTP endpoints using Google API annotations:

- `POST /v1/transactions` - Create a new transaction
- `GET /v1/transactions/{transaction_id}` - Get transaction details
- `PATCH /v1/transactions/{transaction_id}` - Update transaction
- `DELETE /v1/transactions/{transaction_id}` - Delete transaction
- `GET /v1/transactions` - List transactions with pagination

#### Field Constraints
Fields use Google API field behavior annotations:
- `REQUIRED`: Field must be provided
- `OUTPUT_ONLY`: Field generated by server (not settable by client)
- `INPUT_ONLY`: Field accepted in requests only

#### Audit Information
Transactions include automatic timestamps:
- `create_time`: When transaction was created (OUTPUT_ONLY)
- `update_time`: When transaction was last modified (OUTPUT_ONLY)

#### Idempotency
Use `client_token` field for idempotent requests - the same token ensures the same transaction is returned even if the request is retried.

### Schema Metadata

The API uses custom metadata extensions for cross-cutting concerns:

- **Domain**: `payments` (business domain)
- **Owner**: `team-payments` (responsible team)
- **Entity Types**: Marked with metadata (e.g., `line-item`)
- **PII Classification**: Fields can be tagged with PII levels

### Backward Compatibility

The API follows Protocol Buffers best practices for backward compatibility:

- New fields use append-only pattern
- Field numbers are never reused
- Required fields cannot be removed from existing messages
- New optional fields can be added safely

### Proto File Structure

The Payment Transaction API is organized as:
- **Package**: `payments.v1`
- **Location**: `src/main/proto/payments/v1/transaction.proto`
- **Imported Dependencies**:
  - `google/api/annotations.proto` - HTTP binding definitions
  - `google/api/field_behavior.proto` - Field constraints
  - `google/api/resource.proto` - Resource patterns
  - `google/protobuf/timestamp.proto` - Timestamp support
  - `schema/meta/v1/meta.proto` - Custom metadata

### Custom Extensions

The `schema.meta.v1` module provides metadata extensions used across the API:

#### Message Options
```protobuf
option (schema.meta.v1.message_meta) = {
  tags: {
    key: "x-meta-entity"
    value: "line-item"
  }
};
```

#### File Options
```protobuf
option (schema.meta.v1.file_meta) = {
  tags: { key: "x-meta-domain" value: "payments" }
  tags: { key: "x-meta-owner" value: "team-payments" }
};
```

### API Operations

#### Create Transaction
```protobuf
rpc CreateTransaction(CreateTransactionRequest) returns (CreateTransactionResponse);
```

**Request**:
- `parent`: Parent resource name
- `transaction`: Transaction object to create

**Response**:
- `transaction`: Created transaction with generated fields

#### Get Transaction
```protobuf
rpc GetTransaction(GetTransactionRequest) returns (GetTransactionResponse);
```

**Request**:
- `name`: Resource name of transaction

**Response**:
- `transaction`: Transaction details

#### List Transactions
```protobuf
rpc ListTransactions(ListTransactionsRequest) returns (ListTransactionsResponse);
```

**Request**:
- `parent`: Parent resource
- `page_size`: Maximum results per page
- `page_token`: Pagination token

**Response**:
- `transactions`: List of transactions
- `next_page_token`: Token for next page

#### Update Transaction
```protobuf
rpc UpdateTransaction(UpdateTransactionRequest) returns (UpdateTransactionResponse);
```

**Request**:
- `name`: Resource name of transaction
- `client_token`: Idempotency token
- `products`: Updated products

**Response**:
- `transaction`: Updated transaction

#### Delete Transaction
```protobuf
rpc DeleteTransaction(DeleteTransactionRequest) returns (DeleteTransactionResponse);
```

**Request**:
- `name`: Resource name of transaction

**Response**:
- Empty response
